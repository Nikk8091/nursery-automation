## 2. Workflow Template Files

Location: `comfyui/workflows/`. Version-controlled, parameterized JSON node graphs exported from a working ComfyUI instance. The structures below are **representative skeletons** showing the required node types and mutation points — the canonical file is whatever the operator's actual working ComfyUI graph exports to, with these node roles present.

### 2.1 `sdxl_still.json` — scene still generation

Required node roles:
| Node type | Role | Mutated per job by |
|---|---|---|
| `CheckpointLoaderSimple` | Loads SDXL checkpoint | static (set once, not mutated per-job) |
| `CLIPTextEncode` (positive) | Scene prompt text | Visual Prompt Agent — full scene prompt from Phase A2 |
| `CLIPTextEncode` (negative) | Negative prompt | Visual Prompt Agent — Character Bible `negative_prompt_lock` + any QC-critique-appended terms (spec_03 §4.1) |
| `IPAdapterApply` | Character reference injection | Visual Prompt Agent — `reference_image_ids` + `ip_adapter_weight` from Character Bible |
| `ControlNetApply` (canny + openpose) | Pose/structure guidance | Visual Prompt Agent — reference image from Character Bible pool |
| `KSampler` | Sampling | `seed` = Character Bible `base_seed` (+ jitter delta on retry) |
| `VAEDecode` → `SaveImage` | Output | Orchestrator retrieves via `/view` after `/history` reports `complete` |

Skeleton:
```json
{
  "3": {"class_type": "KSampler", "inputs": {"seed": 481920, "steps": 30, "cfg": 7.0, "sampler_name": "dpmpp_2m", "scheduler": "karras", "denoise": 1.0, "model": ["4", 0], "positive": ["6", 0], "negative": ["7", 0], "latent_image": ["5", 0]}},
  "4": {"class_type": "CheckpointLoaderSimple", "inputs": {"ckpt_name": "sdxl_base_1.0.safetensors"}},
  "5": {"class_type": "EmptyLatentImage", "inputs": {"width": 1024, "height": 1024, "batch_size": 1}},
  "6": {"class_type": "CLIPTextEncode", "inputs": {"text": "__SCENE_PROMPT__", "clip": ["4", 1]}},
  "7": {"class_type": "CLIPTextEncode", "inputs": {"text": "__NEGATIVE_PROMPT_LOCK__", "clip": ["4", 1]}},
  "8": {"class_type": "IPAdapterApply", "inputs": {"weight": 0.65, "ipadapter": ["9", 0], "image": ["10", 0], "model": ["4", 0]}},
  "11": {"class_type": "VAEDecode", "inputs": {"samples": ["3", 0], "vae": ["4", 2]}},
  "12": {"class_type": "SaveImage", "inputs": {"images": ["11", 0], "filename_prefix": "__EPISODE_SCENE_ID__"}}
}
```
`__SCENE_PROMPT__`, `__NEGATIVE_PROMPT_LOCK__`, `seed`, and `filename_prefix` are the mutation points the Visual Prompt Agent sets programmatically before `POST /prompt`.

### 2.2 `thumbnail_still.json` — dedicated 16:9 marketing still

Same node structure as `sdxl_still.json` with two differences:
- `EmptyLatentImage`: `width=1280, height=720` (16:9, high-contrast composition prompt appended by the Visual Prompt Agent, e.g. "bold clear composition, high contrast, readable at small size").
- Generated as part of the **same Phase C batch job queue** — same resident SDXL checkpoint, same Character Consistency Gate (§4 below) as every scene still. Never generated by cropping a video frame.

### 2.3 `wan22_i2v.json` — image-to-video (Phase D)

Required node roles:
| Node type | Role | Mutated per job by |
|---|---|---|
| `CheckpointLoaderSimple` (Wan 2.2 TI2V-5B) | Loads video model | static |
| `LoadImage` | Conditioning frame | Video Gen Agent — the **approved** Phase C still for this scene |
| `CLIPTextEncode` | Motion prompt | Video Gen Agent — scene motion description + Character Bible `motion_profile` (beat-bob cues, §4 spec_05 for onset timing) |
| `KSampler` (video) | Motion strength / sampling | `motion_strength` reduced 20%/retry attempt (spec_03 §4.2) |
| `VAEDecode` → `SaveVideo` | Output | 5s clip @ 720p/24fps, retrieved via `/view` |

Skeleton (abbreviated — full graph includes Wan-specific conditioning nodes per the model's official ComfyUI node pack):
```json
{
  "1": {"class_type": "CheckpointLoaderSimple", "inputs": {"ckpt_name": "wan2.2_ti2v_5b.safetensors"}},
  "2": {"class_type": "LoadImage", "inputs": {"image": "__APPROVED_STILL_PATH__"}},
  "3": {"class_type": "CLIPTextEncode", "inputs": {"text": "__MOTION_PROMPT__ + beat_bob_intensity cues", "clip": ["1", 1]}},
  "4": {"class_type": "KSampler", "inputs": {"seed": 481920, "motion_strength": 0.8, "model": ["1", 0], "positive": ["3", 0], "conditioning_image": ["2", 0]}},
  "5": {"class_type": "VAEDecode", "inputs": {"samples": ["4", 0], "vae": ["1", 2]}},
  "6": {"class_type": "SaveVideo", "inputs": {"video": ["5", 0], "fps": 24, "filename_prefix": "__EPISODE_SCENE_ID__"}}
}
```

## 3. Node Mutation Contract

The Visual Prompt Agent and Video Gen Agent are **job builders**, not inference engines. Their responsibility:
1. Load the versioned workflow JSON template from `comfyui/workflows/`.
2. Deep-copy it (never mutate the on-disk template).
3. Replace the marked placeholder fields (`__SCENE_PROMPT__`, `__NEGATIVE_PROMPT_LOCK__`, `seed`, `filename_prefix`, `__APPROVED_STILL_PATH__`, `__MOTION_PROMPT__`, `motion_strength`) with per-job values.
4. `POST /prompt` with the mutated graph.
5. Persist the returned `prompt_id` to `GENERATIONS.comfyui_prompt_id` (spec_02) immediately — before polling begins, for crash-resumability.
6. Poll `/history/{prompt_id}` until `complete`/`failed`/`oom`.
7. On `complete`, retrieve output via `/view` and write an `Asset` row (spec_02).

**No business logic (prompt engineering, retry decisions, QC thresholds) lives inside the workflow JSON itself** — the JSON is a pure execution graph; all decision logic lives in the agent/state-machine layer (spec_03).

## 4. Character Consistency Architecture

**Character Bible schema** (canonical — see spec_02 §3 for the Pydantic model):
```json
{
  "character_id": "duckling_001",
  "name": "Waddles",
  "visual_signature": {
    "species_archetype": "duckling",
    "color_palette": ["#FFD93D", "#FF8C42", "#FFFFFF"],
    "silhouette_notes": "round body, oversized head, no sharp angles",
    "costume": "red rain boots, no other clothing",
    "art_style_tag": "flat-shaded 2D storybook, thick outline"
  },
  "generation_control": {
    "base_seed": 481920,
    "seed_lock": true,
    "reference_image_ids": ["ref_001.png", "ref_002.png"],
    "controlnet_type": "canny + openpose",
    "ip_adapter_weight": 0.65,
    "negative_prompt_lock": "photorealistic, extra limbs, sharp teeth, asymmetric eyes",
    "comfyui_workflow_template": "workflows/sdxl_still.json",
    "thumbnail_workflow_template": "workflows/thumbnail_still.json"
  },
  "voice_profile": {"engine": "ace-step-1.5", "vocal_style_tag": "child-friendly, high pitch, warm", "narration_engine": "kokoro-82m", "narration_voice_id": "af_bella"},
  "motion_profile": {"assembly_mode": "beat_driven_bob", "beat_bob_intensity": 0.4, "sync_reference": "dynamic_onset_grid_isolated_stem"},
  "episode_appearances": ["ep001", "ep003", "ep007"]
}
```

**Drift-prevention pipeline (batch-aware):**
1. Pull Character Bible → lock `base_seed` + `reference_image_ids` for every scene in the episode simultaneously (A2 output feeds all of Phase C's queue at once, including the thumbnail job).
2. Generate all scene stills + thumbnail via the ComfyUI batch job with IP-Adapter reference injection (never seed-alone — seed-alone drifts across different prompts/poses).
3. **CLIP-similarity gate**, applied across the entire batch (stills + thumbnail) before any video generation begins: cosine similarity between each new still's CLIP embedding and the reference pool's embeddings. Threshold: **0.82**. Below threshold → route to `ImageRetryBatch` (spec_03 §4.1) with `consistency_fail` critique + increased `ip_adapter_weight`.
4. Only once every still and the thumbnail pass does the Phase C→D model-swap occur. Approved stills become the Phase D conditioning frames (`LoadImage` node above) — motion generation is anchored to already-validated character designs, not re-interpreted from text alone.
5. Every accepted still is added back into the character's reference pool (capped at ~8 most recent, curated) to allow slow art-direction adaptation without abrupt style breaks.
